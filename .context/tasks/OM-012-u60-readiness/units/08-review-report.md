## Focus areas, answered

1. **Lane correctness.**
   - Ship-now: `Subscribe(int, Action<object,object>, object)`, `Subscribe(int, Action<object>)` returning a handle, and `Unsubscribe(ref int)` all exist in U59 KMonoBehaviour/EventSystem with identical signatures. `OnSelectMaterial(Tag, Recipe, bool)` exists on both (public on U59, private on U60) and is the only overload, so the by-name `[HarmonyPatch]` is unambiguous. `ConfigureScreen` has one overload on both. `Timelapser.CapturePng` is absent on U59, so `Prepare` picks `WriteToPng`.
   - Cecil scan (`scratchpad\RefCheck`): every Assembly-CSharp/firstpass/UnityEngine type and member reference resolves on U59 for SaltySurf (101 refs), UpgradePlanner (1332), CornerBuildAnything (9), JumperBridges (1162), MultichannelCritterSensor (1118), SmoothBorders (1017) and TestRunner (490). Bitshifter's only three misses are `KAnimHashedString[,]` array pseudo-methods. Those are a Cecil artefact and miss on U60 too.
   - The MotionSensorRange.dll and SmartWeightPlate.dll in bin/ are held-lane builds (they reference the context `Add`). Their ship-now source differs only in the copy-settings conversion, which uses the overloads verified above.
   - Held: every change needs U60 API (see the verdict). The partitioner conversion is optional on U60, because the obsolete `Add(Action<object>)` still works there through `_callbackForward`. It is still correctly held, because it cannot run on U59. The Ovagro configs mirror vanilla U60 `VineBranchConfig` / `VineMotherConfig` line for line (`ConfigureCrop(HARVEST)`, `YieldFactor` 1f, `InfoDescription.subtitle`).
2. **Event subscriptions.**
   - `EventSystem.Entry.Invoke` calls `extHandler(context, data)` on both builds, so the `(context, data) => ((T)context).OnX(data)` lambdas get the component and the payload in the right order.
   - The handler is registered on the component's own KObject event system with `this` as context, which is the same pattern vanilla uses (`LogicCritterCountSensor.OnPrefabInit`). No leak: the subscription lives and dies with the object, exactly as the IntraObjectHandler did, and neither the old nor the new code unsubscribed copy-settings.
   - Jumper Bridges keeps both handles. `Unsubscribe(ref int)` removes by id and resets to -1. An `OnCleanUp` without `OnSpawn` passes -1, and `EventSystem.Unsubscribe(-1)` is a no-op (an `idToIndex` miss).
   - Smart Weight Plate (held): the three partitioner entries are still freed through the existing handles. The static lambdas get the plate as context.
3. **Reflection fallbacks.** See findings 1, 4, 5 and 6. Nothing throws at patch time on either build. Salty Surf's `Prepare` keeps Harmony away from a null `TargetMethod`, and TestRunner's two Timelapser patches are mutually exclusive through `Reflect.TimelapserCapturePng`. `Reflect.SelfCheck` lists members explicitly, so the U59-null `TimelapserCapturePng` does not fail the self-check.
4. **GameMode.ps1 blank key.** It cannot misclassify the player's real pointer.
   - The new early return fires only for `present:` followed by whitespace or nothing. A real save path is never blank, and `absent` still returns false.
   - Overwriting happens in `Restore-SaveKey` only when a kept file exists and the current value differs from it. The only case where a blank belongs to the player is a stale kept file (a run that died) followed by the player starting a new colony and quitting before any save, with no run in between. In that case the blank is replaced by the player's older pointer. A blank holds no save path, so nothing is lost. Save files themselves are never touched by this code.
   - Before this change, the same input crashed `Split-Path` and stopped every later run (unit 06, harness bug 2). The game writes the empty value unquoted (`SaveFilenameKey/:` with nothing after it), so the `.Trim()` check matches what the game actually writes.
   - `Timelapser_CapturePng_Patch`: nulling `path` makes U60 `CapturePng` release the owned buffer and return. A run-folder `path` with an outside `secondaryPath` drops only the secondary. `Session.InRunFolder(null)` returns false.
   - `Worldgen.cs`: `Stopwatch` ticks written from the worldgen thread are a 64-bit store on x64 Mono. This is safe, and it removes the Unity `Time` call off the main thread.
5. **Repo conventions.** XML summaries on the new classes (`SurfDescriptors`, `Always<T>`, both patch classes) and one-line comments where the game forces an odd line (`// By name: ...`). Braces are Allman. No new try/catch. Commit subjects are one terse line. The TestRunner README is updated with the code. Reflect handle naming (`TimelapserCapturePng`) matches the neighbouring handles. No issues.
