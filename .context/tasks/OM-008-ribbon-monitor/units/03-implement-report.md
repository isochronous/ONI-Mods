## Deviations from the design, with reasons

- **Atlas 1024 x 1024.** `write_kanim` packs square textures. The artist's 1024 x 512 art does not fit 512 (checked: "sprites do not fit a 512x512 texture").
  - Rewriting through `write_kanim` also recomputes the anim bounds. The artist's export has NaN bounds on every frame (`kanim.py dump` shows `bounds nan, nan`); the shipped kanim has real ones.
- **No missing-wire icon on either port** (`show_wire_missing_icon` false; the Writer uses true). Either port alone is a complete use (monitor, or switch), so an icon would nag on every correctly built panel. The design did not say. **For the user.**
- **Runs of two bits are listed, not ranged:** "9, 10", while three or more become "9-12". The design gives the range format but not the cutoff.
- **Output refresh on Render200ms.** Besides `Redraw`, Render200ms resends the output when `OutputValue != input | switches`. A cut input wire changes `InputValue` with no event, so without this the output would keep the old input bits until the next logic event.
- **Hint line wraps.** It is a `LocText` under a PLib panel, the UpgradePlanner `Widgets` paragraph pattern. A plain PLabel does not wrap, and the line is close to the 280 px width in English and longer in ru.
- **Faded socket.** It is the socket colour at 59 % alpha (`#2E3138`, alpha 150) rather than a fixed blend with the background, so it fades into whatever the side screen draws behind it.
- **"All off" is set to `ButtonBlueStyle`.** PLib's default `PButton` is pink, which in the game means "picked". The design mock is blue.
- **Locations and names.**
  - `anim-original` is at `mods/bitshifter/anim-original/` as the spec says. MultichannelCritterSensor keeps its export inside `src/<Mod>/anim-original`.
  - The screenshot test is `DiagnosticPanelLook.cs`, which leaves `DiagnosticPanel.cs` free for the step 8 suite.

## Looked wrong in the screenshots

1. **Lamps are pastel, not green and purple.**
   - Outside the overlay, the bloom pass adds a glow over the tinted white lamp texture. Green reads as pale lime and purple as pale pink, both with bright centres (screenshot 3).
   - They are still told apart, but purple reads pink rather than #9B59D0.
   - In the automation overlay, where bloom is off, they show their true colours (screenshot 4b).
   - Selected or hovered, the game's highlight washes them to near white (run 1's face shot, screenshots 1, 2 and 4a). Vanilla does that to every building; the lamps just show it most.
   - Possible fixes, not tried: a darker (mid-grey) lamp texture from the artist with bloom kept, the bloom flag dropped from the lamp symbols, or stronger tint colours. This is a question for the user and 3GuB, not code.
2. **Lit lamps cover their large digits.** The bloom symbols draw after the `numbers` layer, so a lit lamp hides its digit except for a faint outline (screenshot 3: digits 1, 3, 9-12, 17 and 31 are barely readable). On unlit lamps the white digits on the dark socket read well. This adds to design point 4 for 3GuB (digit contrast on lit lamps).
3. **The large digit under lamp 31 reads 32** on the face (known art defect, visible in screenshot 3).
4. **The overlay port icons hide some lamps.** In the automation overlay the ribbon port icons sit over the top-left and bottom-left cells and cover lamps 2-3 and 18-19 (screenshot 4b). That is vanilla icon size on the chosen port cells; the user picked the cells.
5. **Build menu icon.** It is the unlit panel, a dark grid with digits. It reads as a grid of numbers at menu size and is not lost on the dark menu (screenshot 5), but it is busy. **For the user**: keep it, or the lit variant the design offered.
